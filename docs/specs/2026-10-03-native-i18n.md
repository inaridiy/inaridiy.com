# Native i18n and official plugins — 2026-10-03

EmDash 1.1への更新に合わせて、英語版を `*_en` shadow fieldからEmDash native i18nへ移し、検索・メール・route cacheを公式実装へ置き換えた。[2026-07-19の不変条件](2026-07-19-content-pipelines.md) のうち「Search reconciliation」「Email and newsletter」のQueue部分はこの文書で置き換える。

## Locale model

- `astro.config.mjs` の `i18n`: `defaultLocale: "ja"`、`locales: ["ja", "en"]`、`fallback: { en: "ja" }`。default localeにprefixを付けない (付けると `/_emdash` adminが404になる)。
- 日本語entryがsource。英語entryは同じtranslation groupの別rowで、translatorだけが作成・更新・公開状態の追従を行う。
- slugはlocaleごと。translatorが作る英語entryのslugは英語titleから決まる。移行で作った英語entryは日本語と同じslug。
- localeを跨ぐリンク (言語切替、hreflang、`/en/about`、OG、likes) は必ずtranslation group (`getTranslations`) から解決する。slugの一致を前提にしない。
- `/en/posts/<slug>` はEmDashのfallback chainで日本語entryに落ちることがある。公開済み英語entryがあれば301、無ければ日本語を `translated: false` として表示し、canonicalは日本語ページ。
- translatable: false (posts.featured_image、activities.date/kind/url) はEmDashがgroup内で同期する。`packages/content-contract` の翻訳fieldと合わせて、seedの全fieldはどちらかに分類される (tests/content-contract.test.mjs)。

## Translator

- 対象は公開済みの `ja` entryだけ。英語entryのhookは無視する (write-backの再入防止)。
- 成功: 英語entryをcreate (`translationOf`) またはupdateし、sourceが公開中ならpublishする。
- 失敗 (Workflowが再試行を使い切った) で、jobがまだ現行sourceを表す場合: 英語entryをunpublishする。古い訳を公開し続けない。
- source unpublish → 英語entryもunpublish。source hashが変わらない再publish → 英語entryを再publish。
- source delete (trash) → 英語entryもtrashへ移し、hash keyを消す。source restore → 一緒にtrashした英語entryもrestoreし (slugを保つ)、次のpublishで再翻訳・再publishする。
- source hashの計算式 (`{model, gatewayId, sourceValues}`、field順) は移行前と同一に保ち、移行済みの訳を再翻訳しない。

## Hook ordering

EmDashの `aiSearch()` (native plugin) のhookはpriority 100、errorPolicy `abort`、timeout 5秒。AI Searchが遅いとchainの後続hookが実行されない。自作pluginは先に走らせる:

| plugin | priority |
| --- | --- |
| translator | 50 |
| newsletter | 60 |
| github-sync (sandboxed) | 70 |
| cache-purge | 90 |
| aiSearch (公式) | 100 |

## Search

- `aiSearch()` が1 entry = 1 documentとしてlocale付きでindexする。D1との毎時照合 (`src/search-index.ts`) と `plugins/search-sync` は廃止。
- AI Search Bindingは `astro dev` でも実accountに届くため、devは `inaridiy-content-dev` instanceを使う。prodは `inaridiy-content`。
- 旧instance `inaridiy-blog-search` は移行確認後に削除する。

## Email

- `cloudflareEmail()` が `EMAIL` bindingで直接送る。`EMAIL_QUEUE` / DLQ consumerは廃止。
- newsletterのdurabilityはoutbox row (`pending` → `sent` / `failed` → `dead`) だけが持つ。旧 `queued` は送信済みとして数える。

## Migration runbook (production, 2026-10-03)

D1 Time Travelの移行前bookmarkを記録してから実行する (`wrangler d1 time-travel info inaridiy-com`)。FTS5 virtual tableがあるためD1全体のexportはできない。

1. `node scripts/migrate-native-i18n.mjs locales --remote` — 既存rowの `locale` を `en` (EmDashの暗黙default) から `ja` へ、共有fieldを translatable 0 へ。
2. KV object cache (`CACHE`) を空にする。
3. i18n buildをdeployする。最初のrequestでEmDash 1.1のcore migrationが走る。
4. `EMDASH_URL=https://inaridiy.com node scripts/migrate-native-i18n.mjs translations --remote` — `*_en` から英語entryを作ってpublishし、`published_at` を日本語に合わせる。KVを再度空にする。
5. `/en`、`/en/posts/*`、`/en/about`、`/en/activities` と言語切替を確認する。
6. `node scripts/migrate-native-i18n.mjs drop-legacy-fields` — `*_en` fieldを削除する。
7. Admin → Cloudflare AI Searchでcollectionを選びSync All Content。`/search` を確認し、旧instanceを削除する。

戻す場合はTime Travelでbookmarkへrestoreし、移行前のcommitをdeployする。
